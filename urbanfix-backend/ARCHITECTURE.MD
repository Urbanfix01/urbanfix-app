INFORME TÉCNICO: ARQUITECTURA DE SOFTWARE
Proyecto: UrbanFix BackendVersión del Sistema: v1.2 (Refactorización Modular)Fecha: 13 de Noviembre, 20251. Resumen EjecutivoEl presente documento detalla la arquitectura técnica del backend de UrbanFix, una API REST desarrollada en Node.js. Esta versión (v1.2) representa una evolución significativa respecto a la versión anterior, migrando de una estructura monolítica a una Arquitectura en Capas (Layered Architecture).El objetivo de esta reestructuración ha sido garantizar la escalabilidad del sistema, facilitar el mantenimiento correctivo y optimizar la comunicación entre la infraestructura de despliegue (Render) y el cliente (Vercel).2. Stack Tecnológico e InfraestructuraLenguaje: Node.js (Runtime Environment).Framework: Express.js (Gestión de rutas y servidor).Base de Datos: Google Sheets (vía Google Sheets API v4).Infraestructura Backend: Render (Web Service).Infraestructura Frontend: Vercel.Autenticación: Service Account de Google Cloud Platform (GCP).3. Arquitectura del SistemaEl sistema sigue el patrón de diseño MVC (Modelo-Vista-Controlador), adaptado para APIs RESTful (sin vistas). La lógica se divide en responsabilidades claras:3.1. Flujo de Datos (Data Flow)El ciclo de vida de una petición (Request) sigue estrictamente el siguiente flujo unidireccional:Entrada: El servidor (app.js) recibe la petición HTTP desde el Frontend.Enrutamiento: El Router (apiRoutes.js) identifica el endpoint solicitado (ej. /crear-solicitud).Procesamiento: El Controlador (solicitudesController.js) recibe los datos, los valida y aplica la lógica de negocio necesaria.Persistencia: El módulo de configuración (googleSheets.js) gestiona la conexión segura con Google y ejecuta la lectura/escritura.Respuesta: Los datos retornan al controlador, se formatean como JSON y se envían al cliente con el código HTTP correspondiente (200, 201, 500).5. Documentación de Endpoints (API)A continuación se detallan los puntos de acceso disponibles en la API v1.2:Método HTTPEndpoint (Ruta)Descripción FuncionalGET/api/solicitudes-sheetRecupera todas las filas de la hoja, normaliza cabeceras y devuelve un array de objetos JSON.GET/api/dashboard-summaryRealiza cálculos en el servidor para devolver métricas clave: Total, Pendientes y Finalizadas.POST/api/crear-solicitudRecibe un JSON con datos del formulario e inserta una nueva fila al final de la hoja.PATCH/api/update-solicitudActualiza celdas específicas de una fila existente (Estado, Presupuesto, Monto).DELETE/api/eliminar-solicitudLimpia el contenido de una fila específica sin eliminar la estructura de la hoja.6. Mejoras Implementadas en v1.2La refactorización ha introducido las siguientes optimizaciones críticas:Manejo de Errores Centralizado: Se implementó un Middleware global en app.js que intercepta cualquier fallo del sistema. Esto previene la caída del servidor ("Crash") y asegura que el Frontend siempre reciba una respuesta estructurada, incluso en caso de error.Seguridad de Credenciales Híbrida: El sistema ahora detecta automáticamente el entorno:En Desarrollo (Local): Carga credenciales desde el archivo credentials.json.En Producción (Render): Carga credenciales desde Variables de Entorno seguras, evitando exponer claves privadas en repositorios públicos.Configuración CORS Dinámica: Se establecieron reglas de Cross-Origin Resource Sharing (CORS) que permiten la comunicación segura entre los dominios de Vercel (incluyendo entornos de preview) y el servidor en Render.7. Procedimientos de EjecuciónPara iniciar el servidor en los diferentes entornos, se definen los siguientes scripts en package.json:Entorno de Producción: npm start (Ejecuta node src/app.js)Entorno de Desarrollo: npm run dev (Requiere nodemon para reinicio en caliente).
